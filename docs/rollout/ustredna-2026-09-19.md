## Výkon a otvorené merania

- Prostredie: Amazon Linux 2023, x86_64, Linux 6.18.49, 8 dostupných CPU; lokálny PostgreSQL 17, syntetické dáta. Nie produkčná kapacita.
- História: 20 súbežných klientov, 10 000 riadkov, 100 SQL vyhľadávaní; **SQL p95 209,9 ms**. Nezahŕňa HTTP, autentifikáciu, PostgREST ani vzdialenú sieť; nesplnenie/naplnenie API cieľa 800 ms z toho nevyplýva.
- Case store: 20 mock klientov, 60 read požiadaviek vrátane štartu za 60 s; burst 20 invalidácií/2 s sa zlúči na najviac 80 read požiadaviek spolu. Je to počet volaní mock fetch, nie databázových dopytov ani baseline celej aplikácie.
- [Instrumentovaný service test](../../src/server/case-collaboration-workload.test.ts) používa skutočné `loadCaseLiveSnapshot`, mapovanie a notification repository; iba Supabase hranica je lokálny počítaný fake. Pre **20 klientov ×100 kariet** po oprave: studený štart **60 service requests +60 notification queries +120 RPC** (spolu 180 downstream volaní); nezmenený stav aj jedna úplne zlúčená dávka 20 zmenených kariet **20+20+40** (spolu 60). Pred opravou bolo cold-start volaní 16 180 a pri dávke 3 260. Per-card detail fetch bol odstránený; nezavádza sa odhad počiatočných revízií.
- Nový snapshot vracia **najviac 40 kariet na stránku**, najnovších 200 udalostí na kartu a najnovšiu prijatú polohu; contacts/vehicles/locations/profiles deduplikuje. Dáta a revízie pochádzajú z jedného SQL/MVCC snapshotu. Acknowledgement zahŕňa len nezmenené alebo doručené karty. Pridaný index `(organization_id, case_id, created_at DESC, id DESC)` chráni event-dense čítanie; existujúci location index zostáva.
- Skutočný lokálny PostgreSQL benchmark: **20 klientov, 100 kariet, 22 206 events, 60 snapshot RPC** na cold start; **RPC p95 538,5 ms** vrátane lokálneho prenosu/dekódovania JSON. `EXPLAIN` potvrdzuje využitie nového event indexu. Test dokazuje aj stránkovanie po 40 kartách, resource/revision súlad pred/po súbežnom commite, najnovších 200 udalostí a prijatú polohu klienta. Nezahŕňa HTTP autentifikáciu, notifikačný read, final authorize ani vzdialenú sieť.
- AC26 zostáva **čiastočne overené**: cold-start query fanout je vyriešený a reálna lokálna SQL záťaž zmeraná; chýba baseline celej aplikácie, vzdialený HTTP p95 a websocket→UI meranie. Nie je to certifikácia produkčnej kapacity. Artefakty: `.context/collaboration/service-workload{,-before}.json`, `sql-workload.json`; reprodukcia cez uvedené service/SQL testy.
- Heartbeat obnovuje iba TTL; bežná obnova neposiela broadcast všetkým klientom. Eventy nesú `{}`, dáta sa čítajú autorizovane. Realtime nenahrádza autorizáciu.

## Návrat späť

- Zablokovať vydanie pri nesprávnom prijatí session, strate draftu, ACL úniku, neatomickom save, nepravdivom summary alebo neovládateľnej hlavnej akcii na mobile.
- Použiť existujúci feature prepínač iba tam, kde skutočne existuje; inak kompatibilný revert aplikačného commitu štandardnou PR cestou. Neexistuje jeden zavedený univerzálny prepínač celej tejto etapy.
- **Nedropovať nové tabuľky/RPC ani nemažte nové prípady/callbacky.** Staršia kompatibilná aplikácia môže nový additive schema ignorovať. Odstránenie RPC spod bežiacej novej aplikácie nie je bezpečný rollback: aktivovaná spolupráca údaje skryje.
- UI rollback nemení uloženú konfiguráciu smerovania. Potrebnú opravu uloží oprávnený správca ako novú auditovanú verziu; neobnovovať historický plán automaticky.
- Nevyvolať reload uprostred hovoru/draftu. Po návrate overiť prijatie presnej session, globálny callback počet, históriu, starý routing editor, čítanie poznámok/úloh, zachovaný draft a reconnect.
- Zachovať jediný existujúci cron `*/5 * * * *` → `/api/telephony/cron` s `CRON_SECRET`; žiadne workers/listeners/schedulers.
