## Zvolené dátové a prístupové kontrakty

Nasledujúce názvy nových entít sú návrh pre implementáciu, nie existujúce tabuľky. Nevytvárať druhý všeobecný workflow engine.

### Partner a prípad

- Partner = existujúci `motorist_partner_directory.id` v jednej organizácii. Nová explicitná väzba linka → partner sa ukladá a validuje organizačne; voľné meno zostane kompatibilný zobrazovací údaj. Chýbajúce alebo neplatné mapovanie znamená ručný výber, nikdy odhad podľa mena/telefónu. Pri vzniku prípadu uložiť partnera pôvodu, zdrojový call/line ID a historický názov; zmena mapovania neprepíše staré prípady. Dispečer pred uložením môže predvoľbu opraviť.
- Nová väzba prípadov `assistance_followup` má organization, parent consultation ID a child assistance ID, autora, čas a command ID. Atomické založenie dieťaťa aj väzby; žiadne self/cross-org/cyklické väzby. Jeden konzultačný prípad môže mať viac vedome vytvorených asistencií. Opakovanie rovnakého zámeru vracia to isté dieťa, nový vedomý zámer môže založiť ďalšie. Nekopírovať automaticky interné poznámky ani celé prílohy.
- Partnerské členstvo je oddelené od `motorist_profiles` a towing členstva: auth user ID + organization ID + partner directory ID + active/invited/disabled + membership version. Správca pozve konkrétny overený kontakt cez module-aware onboarding podľa kontraktu nižšie; prijatie preukáže kontrolu účtu. Partner si sám nevyberá partner ID ani rolu. Zmena partnera znamená odobratie starého a nové schválené členstvo, nie prepis historických auditov. Zmena verzie/revokácia účinkuje na ďalšiu požiadavku aj so starým JWT.
- Onboarding má explicitný modulový cieľ a serverový invitation intent: organization, partner/field membership, pozývajúci, overený cieľový auth user alebo pending provisioning, stav a expirácia. Pozvanie → prijatie → nastavenie/password-completed → callback → oprávnený modul; expired/revoked pozvanie nedá aktívne členstvo, reinvite vytvorí novú generation a zneplatní starú. Reset hesla je dostupný aj členovi bez dispatch profilu a nemení jeho roly. Existujúci auth účet vrátane field účtu sa bezpečne spojí s novým partner membership bez vytvorenia `motorist_profiles`; po prihlásení môže vybrať iba serverom overené moduly. Query parameter ovplyvní prezentáciu, nikdy autorizáciu. Deaktivácia člena/pozvania zastaví callback aj starú session na ďalšom resource requeste. Pri výpadku medzi Auth provisioningom a membership commitom sa rovnaký intent obnoví podľa zaznamenanej provenance/receipt; neznámy účet sa neprisvojí iba zhodou emailu, nevytvorí sa duplicitný účet ani sa nemaže existujúci účet s iným členstvom. Neoveriteľný výsledok ostáva pending na kontrolované vyriešenie. Konkrétne zmeny: `src/server/access-management.ts:643`, `:675`, `src/app/api/auth/password-completed/route.ts:9`, `src/components/auth/SetPasswordForm.tsx:141`, `src/server/towing/memberships.ts:25` `src/app/auth/callback/route.ts`, `src/app/api/auth/forgot-password/route.ts`, `src/app/api/towing/auth/forgot-password/route.ts` a nový partner invite/reset server vstup; zachovať existujúce towing provisioning recovery pravidlá.
- Zdieľanie je explicitná väzba partner ↔ prípad s povolenou verziou výstupu, autorom a odvolaním. Partner pôvodu automaticky neznamená prístup ku všetkým detailom; dieťa ani jeho prílohy sa nededia. Minimum portálu: zoznam vlastných zdieľaných prípadov, detail povoleného výsledku, potvrdené dokumenty. Nie telefónia, interné poznámky, ceny asistencie, globálny adresár, GPS ani celé dispatch DTO. Partner je v prvej verzii read-only; servisné prijatie zaznamenáva oprávnená kancelária s dôkazom.
- Partner-service settlement je samostatný podklad viazaný na konzultáciu: partner, objednávateľ/platiteľ služby, dohoda a jej verzia, účtovateľnosť, schválená suma v centoch alebo neurčená, mena, schvaľovateľ a audit. Predvoľba je nenacenené, nie nula. Odporúčanie servisu, odoslanie výstupu a potvrdené prijatie vozidla sú tri nezávislé fakty. Report rozlišuje počet hovorov, konzultácií a výkonov. Asistenčný platiteľ a towing ceny ho nemenia. V jadre ide o zúčtovací podklad/export; nevzniká nový fakturačný systém.

### Jedna identita výkonu, špecializované vykonanie

- Nová trvalá `operation` má ID, organization, voliteľný case ID, druh (tow/delivery/collection/transfer), branch scope, execution owner, revíziu, creator/command identity a časové údaje. Owner je buď jedna existujúca towing order, alebo logistický execution record. Owner reference je unikátna v organizácii a nedá sa počas aktívnej práce potichu vymeniť. Spoločný zoznam číta projekciu vlastníka, nevlastní druhý nezávisle editovateľný stav.
- Odťahová zákazka naďalej vlastní vodiča, workStatus, finančné stavy, doklady a úhrady. Pri vyzdvihnutí náhradného auta odťahovkou existuje **jedna operation** s towing ownerom a logistickým kontextom cyklu, nie druhé vykazované vykonanie. Partner report počíta `distinct operation.id`; fyzické doručenie sa môže dokladovať towing odovzdaním, kontrola pripravenosti zostáva samostatná.
- Logistická operation vlastní pridelenie, prijatie, priebeh a vykonanie. Handoff je jej publikovaný náhľad/prístup, nie časový život práce. Handoff/mobile command sa v jednej transakcii preloží na ten istý logistický stav; web aj starý kompatibilný mobil menia rovnaký execution owner. Expirácia/revokácia grantu zruší prístup, nie operation, návrat ani prenájom. Explicitné zrušenie práce vyžaduje samostatný oprávnený príkaz s dôvodom. Towing owner sa nikdy nedokončuje cez všeobecný handoff command.
- Pre existujúce handoffy vytvoriť jednoznačné mapovanie na operation pri kontrolovanom backfille; historické udalosti a tokeny sa nemenia. Atómový migračný prechod musí zosúladiť dáta, indexy aj všetky issue/publish/command RPC: nové granty majú unikátny aktívny slot `(organization, operation)`, legacy issue bez operation používa najviac jeden samostatný legacy slot na prípad. Legacy get/read/write vracia len legacy/kompatibilné karty, nikdy web-only collection stavy. Staré command IDs zostanú opakovateľné. Nesmie vzniknúť medzistav, keď index dovoľuje niečo, čo starý RPC nesprávne prepíše alebo odmietne.
- Prvé nové pristavenie môže použiť existujúci mobilný lifecycle a jeho presný wire tvar. Nové collection/transfer údaje a podrobné potvrdenia sú na oddelenom web API; mobil ich nedostane ako neznámy enum/pole ani cez prekročenie existujúcich limitov zoznamov. Existujúce legacy karty ostávajú funkčné. Paginovaný webový zoznam sa nerobí N+1 načítaním všetkých prípadov.

### Dlhodobý cyklus auta a dostupnosť

- Lokálny `vehicle_use_cycle` = potvrdené fleet asset ID + lokálny cycle ID + pristavenie/klientsky kontext + voliteľná overená externá rental referencia. Je to zoskupenie miestnej logistiky, **nie** tvrdenie o nájomnej zmluve SWHouse. EČV, posledný `rentTo` ani observation timestamp nesmú samy určiť cyklus. Nejasné historické prenájmy sa nebackfillujú odhadom.
- Cyklus obsahuje návratový záväzok: vyzdvihneme / klient vráti / nedohodnuté / pokračuje, voliteľný termín, vlastníka ďalšieho kroku a odkaz na nanajvýš jeden aktívny návratový zámer. Zmena termínu aktualizuje existujúci návrat pod revíziou. Úmyselné storno/opätovné založenie zachová históriu a aktívnu unikátnosť. Cyklus aj operation prežijú uzavretie prípadu a expiráciu tokenu; hard-delete prípadu nesmie kaskádovo zmazať otvorený cyklus/výkon.
- Pri výmene sa spoja dva odlišné cykly/vozidlá a dva výkony: nové doručenie + prevzatie pôvodného auta. Nevytvárať jedno auto s prepísanou identitou. Klientovo vlastné vrátenie je udalosť bez fiktívnej jazdy.
- Pridelenie je zodpovednosť a viditeľnosť vo fronte, nie rezervácia kapacity ani fyzický štart. Vodič môže mať päť pridelených úloh bez vymyslených intervalov (S4:112–114, 186–194; towing fixture už viac pridelení podporuje). Potvrdenie kapacity/časového intervalu a štart práce sú samostatné kroky s atomickou kontrolou kolízií. Nepotvrdené queued pridelenia neblokujú ďalšie queued pridelenia; nesľubujú však dostupnosť. Timestampy UTC, UI Europe/Bratislava, potvrdené intervaly [od,do) vrátane presunu. Prekrytie rovnakého vykonávateľa alebo kapacitného zdroja sa odmietne pri potvrdení/štarte; fyzická práca s neznámym koncom bráni potvrdiť ďalšiu kolidujúcu kapacitu, kým sa nevyrieši. Žiadny tichý override. Revízia/generation chráni prepridelenie a starý vodič už nemení stav. Historické `startedAt` s `startSource='assignment'` nie je fyzický štart a nebackfilluje sa do confirmed intervalov: dnešné assign a start sú odlišné (`supabase/migrations/20261013120000_towing_work_orders.sql:321`).
- Zdroje majú odlišné roly: vykonávacie vozidlo (napr. odťahovka) a vodič spotrebúvajú kapacitu; prepravovaný predmet/poškodené klientovo auto nie je tým istým zdrojom; náhradné auto cyklu má vlastnú overenú identitu. Potvrdenie intervalu kontroluje iba relevantné zdroje daného typu. Čerstvé voľné SWHouse údaje sú gate nového použitia náhradného auta a pripravenosti, nie univerzálny gate každej operácie. Vyzdvihnutie aktuálne prenajatého auta v potvrdenom cykle je dovolené; nesmie sa tým uvoľniť na nové vydanie. Odťahovka ani poškodené klientovo auto nepotrebujú fiktívny SWHouse rental záznam (`src/domain/types.ts:519`).
- Pri potvrdení kapacity/štarte krátka DB transakcia zamkne relevantné auto/vodiča v stabilnom poradí, znova overí aktuálne intervaly, členstvo, generation a dostupný source snapshot. Unikátne obmedzenia kryjú jediný aktívny assignment na operation (nie jedinú queued úlohu na vodiča) a návratový zámer. Sieť/provider volania nie sú v transakcii. Externý SWHouse zápis/reservation lock nie je dostupný kontrakt: UI nesľubuje zaručenú rezerváciu mimo tejto aplikácie.
- Pripravenosť = potvrdená kontrola + čerstvé voľné SWHouse dáta + overené párovanie + bez interného bloku/kolízie. Súčasný freshness limit je 10 minút (`docs/live-fleet.md:16`); pred použitím potvrdiť existujúcu implementáciu, nepridať druhú odlišnú politiku. Výpadok/neznámy stav zostáva neoverené, nie voľné. Draft práce možno pripraviť, nové použitie náhradného auta blokuje rozpor; návrat existujúceho cyklu tento free gate nevyžaduje.

### Webové priestory a dôkazy

- Zachovať cookie session a existujúce oddelené memberships. Dispatcher používa spoločný shell s pretrvávajúcou telefóniou a rozpracovaným prípadom; moduly sa načítajú až po otvorení. `/zakazky` a `/vodic` ostanú kompatibilné priame vstupy. Nový `/moje-jazdy` pre deliver-only a `/partner` neimportujú dispatch repository ani telefóniu. Zdieľa sa navigačná prezentácia, nie globálny prefetch citlivých dát. Samostatný scope resolver vyhodnotí user, organizáciu a povolené moduly pred načítaním dát.
- `deliver` neznamená `drive`, dispatch profil neznamená towing billing oprávnenie. Koordinátor má iba povolené pobočky, fakturant existujúce `price/bill/cash`, partner vlastné explicitné shares. Na serveri opakovať kontroly list/detail/mutation/export/attachment; skryté menu nie je autorizácia. Same-origin mutácie, no-store súkromné odpovede, žiadne user_metadata oprávnenia. DB service-role RPC musí znovu overovať odvodený user/member/version, nie veriť parametrom klienta. Súbory proxy cez server s kontrolou oprávnenia pri každom čítaní.
- Pristavenie: potvrdiť odovzdanie klientovi. Vyzdvihnutie: osobitne prevzaté od klienta, doručené do cieľa, kontrola auta. Pri každom odovzdaní osoba odovzdávajúca/preberajúca, čas, základné fotografie; dostupné km/palivo so zdrojom, časom merania a vedomým potvrdením. Chýbajúce hodnoty sú null s dôvodom. Telemetria sa neprezentuje ako ručne potvrdená. Predvolený návrh minimálneho dôkazu je fotografia pri prevzatí a pri odovzdaní alebo zdôvodnená výnimka; Eros potvrdí požadovaný počet pred pilotom.
- Kompatibilný mobilný `complete` bez nových polí zachová fyzický pracovný výsledok, pôvodný receipt a strict DTO; nepridá automaticky dôkazy, ktoré starý klient neposiela (`src/lib/mobile-api.ts:453`; `src/server/mobile/delivery.ts:44`, `:87`). Úplnosť odovzdávacích dôkazov je oddelený evidenčný výsledok na tom istom execution ownerovi: web ukazuje **Vykonané · dôkazy čakajú**, nie druhý workStatus alebo druhé dokončenie. Oprávnený používateľ cez web doplní konkrétny dôkaz s autorom, zdrojom, časom a prípadným potvrdením pôvodného vykonávateľa; kancelária nemôže za vodiča nepravdivo potvrdiť meranie alebo odovzdanie. Nezistené údaje ostávajú nezistené a výnimka s dôvodom sa neoznačí za pozorovanú hodnotu. Post-completion doplnenie má osobitné serverové právo a revíziu; neobnovuje expired/revoked grant ani kontaktový prístup starého vodiča. Readiness/finálna evidencia sa neoznačí za splnenú, kým nemá potrebné dôkazy alebo výslovne povolenú zdokumentovanú výnimku. A22 dokazuje starý fyzický tok; A23 samostatne pravdivú evidenciu na tom istom operation ID.
- Základ poškodenia: fleet asset + cycle/operation, popis, fotka alebo zdôvodnená nedostupnosť, autor, čas, riešiteľ a stav. Neskoršie opravy rozšíria rovnaký záznam. Nezamieňať s klientskou správou o nehode.
- Každý write má command ID, hash obsahu, expected revision, audit a potvrdený receipt. Rovnaký ID/obsah vracia výsledok; rovnaký ID/iný obsah sa odmietne. Timeout = výsledok nepotvrdený a overenie toho istého príkazu. Nová webová logistika nevytvára offline queue; existujúce towing offline správanie ostáva.
- Partnerský výstup sa explicitne zverejní ako nemenná verzia s potvrdeným príjemcom a redukovanými poľami. Odoslanie má samostatné intent ID, document hash a provider result (pending/accepted/unknown/failed); accepted nie je doručenie. Neistý email sa automaticky neposiela znova po vypršaní provider dedupe okna: preverí sa pôvodný výsledok alebo operátor vedome vytvorí nový auditovaný send intent. Nie nový background worker.

## Release gates, riziká a stop pravidlá

1. Lokálny contract gate: jednotkové + izolované DB race/security/compat testy, typecheck, lint, existujúca build brána. TEST fixtures len syntetické. Lokálne DB skripty nikdy nepresmerovať na vzdialenú URL. Plán sám testy produktu nevykonal.
2. Schema gate: nové additive schema + explicitný backfill + index/RPC prechod (manifest všetkých writerov: dispatcher handoff, public token, member handoff, app assignment a existujúci towing command, nie iba nové operations API) musia byť otestované spoločne pred povolením UI. Pripraviť presný migration manifest, očakávané počty/unikátnosť a rollback-forward postup; remote TEST `nzpnqdstvkfncflgqlny` iba po oprávnení pre konkrétne SQL. Nevynútiť downgrade starého indexu, keď už existujú súbežné operations: vypnúť nové vstupy, zachovať dáta a opraviť dopredu. Chýbajúca schema → modul nedostupný, nie fallback do nesprávnej DB.
3. Každý PR z aktuálneho dev cez pracovnú vetvu/Preview do dev, povinný existujúci `Vercel – pomoc-motoristom-dispatching`. Preview bez live integrácií. Stable TEST výhradne `https://test.dispecing.linkapomoci.sk`, projekt `pomoc-motoristom-test`, presný projekt ID podľa AGENTS.md; porovnať health verziu a deployment Git SHA. Preview a TEST zdieľajú DB: nepovoliť polovičný contract pre starý deploy.
4. Produkcia `ifpaeegaesdmljfkdvcn` a `https://dispecing.linkapomoci.sk` ostáva oddelená. Žiadna produkcia na základe plánovacej požiadavky. Budúci release PR musí uviesť tested SHA, plný diff a majiteľovo schválenie; rozšírený dev scope vyžaduje nové overenie/schválenie. Žiadne bulk pending migrations/seeds, nové schedulery, pracovníci/listenery, nové live Preview integrácie alebo kontaktovanie historických zákazníkov.
5. Čiastočný checkpoint možno odovzdať s presným rozsahom; P3 pilot nie je hotový celý produkt. Úplný core stop condition = P7 + A01–A18/A21–A24 PASS vrátane A06, bez nevyriešeného IDOR, dvojitého výkonu/financie alebo strateného návratu. A19 a rozšírený A20 sú neskoršie flotila/kalendár; ich neprítomnosť neblokuje core. Základ konfliktov z A09 už blokuje core.
