# Verified callback targets (R07)

Local implementation only; no Supabase migration, deployment or Telnyx call was performed. Apply solely to this copy after explicit authorization, in migration order after the callback-contact and task-workspace migrations. Keep the task writer inventory/deployment requirements in `tests/postgres/COMPATIBILITY.md`.

Deploy the compatible application before configuring any policy. Before this migration, only the combined missing-resolver (`PGRST202`) and missing-policy-table (`PGRST205` / `42P01`) response preserves ordinary dialing. An existing policy table, permission failure, malformed result or outage fails closed. The migration requests PostgREST schema reload. Verify that the resolver **and** policy RPC are visible after reload before configuring a policy; a jointly stale schema cache cannot prove physical absence and is not an activation signal.

Directory managers/admins mark a source contact as unable to accept callback calls. An optional target must be another existing contact in the same organization, explicitly verified with the current phone numbers. No target means calling is blocked. Phone edits invalidate verification; previously marked source numbers stay blocked. Names, branches and history never imply a destination. A target already marked noncallback is rejected. Multiple source policies for the same number block ambiguous resolution.

The caller sees both original and verified target names/numbers and confirms each alternate call. Generic outbound requests retain the original `to` and carry `callbackTargetVerificationId`; callback requests carry `verificationId`. The server revalidates before creating a call. Callback approval binds the exact request, actor, original number, target and immutable verification. The link RPC freezes that binding into the new outbound session before reservation/provider commands. Customer contact proof keeps the actual dialed number and the separate binding; only that obligation can be fulfilled, never sibling requests. Revocation prevents a new call but does not invalidate an already captured historical contact fact.

Validation: `python3 tests/postgres/callback-target-contract.py` uses only `127.0.0.1:55432`, database `callback_target_contract`, and applies the exact callback, task-workspace and target migrations. Unit tests cover pre-migration fallback, strict errors, confirmation and endpoint authorization. Full provider acceptance remains external: explicitly authorized alternate callback, audible customer/operator proof, exact obligation fulfillment, mobile own-device behavior, caller ID, and ordinary unknown-number calls. No additional scheduler or provider is introduced.
